# 覆盖、批注与复杂报告复核

## 读取检查结果

build_review.py输出content-audit.json。已有JSON或HTML也可独立检查：

```powershell
python E:/Nolva/skills/report-revision-comparison/scripts/audit_review.py 'package.json或HTML绝对路径' --old '对应旧稿.docx' --new '对应新稿.docx' --out '新的content-audit.json'
```

传入源稿时按包内SHA-256核对身份，不能用文件名代替。未传源稿时批注状态为not_checked，不能当作源稿无批注。PDF批注目前不支持提取，明确披露并另查原件。

结果按旧/新、正文/标题/表格/图件分别统计提取、配对、变化、页面定位及字形映射。unmatched保留源位置和摘要；source_coverage保留提取器已知遗漏。计数的分母是已提取块，不证明源Word全结构完整。批注属于独立信息，不计入正文配对率。

## 分流和复核

章节大幅重构、大面积重写、重要结论/数值/规范未配对或结构关系复杂时，采用复杂复核。脚本的review_required是待检查提示；空行、封面重复等可以在实际阅读后说明排除，不为小噪声强制人工逐块改配，也不只凭一个固定配对比例决定是否通过。

脚本会列出跨类型配对、低相似文本、低记录置信度、拆合/重组/移动关系。默认相似度0.30只是可调整的筛查启发值，低于它不证明错配，高于它不保证正确。重要未配对项不因未被算法识别而退出审阅。

复杂复核覆盖各章的代表性变化及重大结论、数值、单位、标准、解释边界，优先查看提示清单。对照上下文确定一对一、拆分、合并、重组、移动或真正增删；无法确认时保持未配对并披露，不靠逐段顺序强配。已有原生Word比较可作为补充证据，不能未经检查直接视为语义对应。

通过现有引擎事务保存补配和真实执行来源；method=human是当前引擎人工改配接口标签，并不证明专家参与或人工核实，actor应写实际AI/人员身份，未确认关系保持needs_review。置信度需有依据，不将所有补配统一设为高分。

在本次工作记录中简记审过的章节/关系、重要遗漏的处置和未解决范围。重要配对仍不确定时，成果可标为部分比较并给出限制，不能作为完整修订对照交付。用户只要效果样本时可保留局限，不擅自扩展为逐处修复原报告。

## Word批注独立对账

脚本从两版Word的comments.xml逐条提取，包括表格锚点、源作者及日期字段。作者字段仅是源元数据，不自动取得专家身份。comment inventory中保留source_comment_id、原文、锚点XML位置和候选块；候选块不代表目标已人工确认。

按文档身份、批注原文规范化后的多重集与HTML意见对账；相同内容的两条批注需分别登记。规范化只忽略空白。改写后的意见可能被标为未导入，需要核对真实来源，不为消除提示重复导入。

需要在HTML呈现时，按annotations.md登记有来源的意见，关联已核实的候选块；无法定位时保留未定位意见清单，提供原文、源位置及来源，必要时随交付附上。不要删除表格意见、猜配到相邻段落或把Word作者直接标成专家。该脚本只生成清单，不修改包、不自动判定意见处置。

## 三类验收

- 运行与打包：固定发布资源、源身份、哈希、离线无网络、导出重开及基本交互。
- 比较覆盖与语义：提取遗漏、未配对内容、结构重写、意见对账及原因/影响的来源与覆盖。无原因材料允许未登记，不要求每一处填满。
- 原页呈现与定位：检查实际页面、关键数值/单位/图表及删除线/下划线；缺坐标时转文字审阅，不猜画。

三类结果各自记录通过、部分或未验证，不能互相替代。自动报告的semantic_acceptance=not_assessed与delivery_complete=false不由计数自动升级；实际核查结论在本次交付记录说明。保留真实样本工作路径与问题类型供以后算法改进，不把私人报告打包进共享Skill。
